## 3. 方案
注意：checkout 每筆送 PAYUNi 的 `ReturnURL/NotifyURL/BackURL` 都由程式帶參數（core.ts origin），**PAYUNi 後台通常不必改**；但要請 Elsa 在 PAYUNi 後台確認沒有綁定網域/IP 白名單限制。

### (A) 搬進我們的 Vercel 專案（Next.js API routes）— 推薦
- 做法：把 create/checkout/notify/return/status/test/create、Resend 寄信移植到 vercel-win/app/api；D1 → Neon Postgres（Marketplace，Drizzle 可沿用 schema，改 pg dialect）；限流可用同 DB 或 Upstash。PR #30 的改動一起帶進來；origin 改 2027course.win-lin.com，/api/payuni/create proxy 改成本地。
- 需要的環境變數：PAYUNI_MER_ID、PAYUNI_HASH_KEY、PAYUNI_HASH_IV、PAYUNI_TEST_ACCESS（可自己產）、RESEND_API_KEY、RESEND_FROM、RESEND_REPLY_TO、DATABASE_URL（Neon 自動注入）。
- **目前 Vercel env 只有 PREMIERE_PAGE_ENABLED，上述值全都沒有**，要 Elsa 從 PAYUNi 後台、Resend 後台提供（或她自己貼進 Vercel）。Resend 寄件網域需已驗證。
- 舊訂單/已付款名單：在舊 D1 裡，我們讀不到。請 Elsa 從 PAYUNi 後台匯出交易明細＋Resend 寄信紀錄當已付款名單；（也可請 ChatGPT Sites 匯出 D1，但那要經她的 ChatGPT）。新系統從零開始。
- 漏單風險：切換點前在舊站建立、還沒付完的單，notify 仍回舊後端（舊後端照常運作、照常寄信），不會漏，只是記錄分散兩處 → 對帳以 PAYUNi 後台為準。切換本身只是改 proxy，可秒切、可回滾（還原 PR）。
- 工作量：約 0.5–1 天開發＋Preview 測試（PAYUNi 正式環境 preview 網址受保護，notify 會被 Deployment Protection 擋，需用 production 或 bypass 測），＋ NT$1 真人刷卡驗收。
- 優點：同一平台、同一 repo 自動部署、我們有權限；不需 Cloudflare 帳號。

### (B) 我們自己的 Cloudflare Worker + D1
- 程式改動最少（D1/Workers 原樣），但要自建 wrangler.toml、D1、自訂網域（如 api.win-lin.com DNS 在哪要查）。
- **我們沒有 Cloudflare 帳號/token**，需 Elsa 開帳號或給 API token，加上同樣的 PAYUNi/Resend 秘密。舊資料、漏單處理同 A。
- 工作量：約 0.5–1 天＋帳號設定；多一個平台要維護。

### (C) 其他
- C1 維持舊後端不動，只在 Vercel proxy 層處理：可把 return 導回 2027course（攔截 /payment），但 PAYUNi 品名、email 主旨、NT$1 測試重用舊單的問題**改不到**。只能當暫時方案。
- C2 由 Elsa 自己在 ChatGPT Sites 套 PR #30 publish：最快，但違反「不經 ChatGPT Sites」，且快照可能過舊。

## 4. 風險清單
1. 秘密外流/貼錯：HashKey/IV 必須只放 Vercel env（Sensitive），不進 repo。
2. 雙後端期間對帳分散：以 PAYUNi 後台交易為準。
3. 新後端 notify 驗簽、寄信冪等若移植出錯 → 已付款未標記或重複寄信；要搬 checks/payment.test.cjs 的 16 項測試並跑通。
4. Deployment Protection 會擋 PAYUNi 打 preview 的 notify → 只能 production 驗收或設 bypass（要動設定，需同意）。
5. PAYUNi 後台若有網域白名單/固定 NotifyURL 設定 → 需 Elsa 確認/修改。
6. Resend 寄件網域 DNS 未驗證則信件寄不出。
7. 舊站 signature-speaker 仍對外可報名，可能有人從舊網址付費 → 建議切換後請 Elsa 決定是否下架。
8. 切換仍需真人 NT$1 刷卡＋可收 floraloasis0211 信箱的人驗收。
